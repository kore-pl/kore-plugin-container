# Плагин управления контейнерами（kore-plugin-container）

## Обзор

Плагин управляет существующими контейнерами через установленную на хосте CLI `docker`: список, краткий осмотр, логи, запуск/остановку/перезапуск и однократный сбор статистики. Он не включает Docker SDK, встроенную среду или прямое подключение к сокету демона (G-05 / G-17): каждое внешнее действие — подпроцесс `docker` с фиксированным argv (без shell). Отсутствие CLI, недоступный демон или не-Linux платформа возвращают `E_UNSUPPORTED` без скрытого переключения и выдуманных данных.

## Поверхность протокола

Протокол `kore.plugin.v1`, `lifecycle=lazy`, `depth_level=basic`, возможности `system:read` + `system:admin`. Двенадцать бизнес-методов: `list` / `inspect` / `logs` / `stats` / `health` / `images` / `pull` / `rmi` / `update` / `start` / `stop` / `restart`, все с префиксом домена `container.`. `container.exec` / `shell` / `attach` намеренно не предоставляются (ADR-0018) и возвращают `E_UNSUPPORTED` до обращения к docker. stdout handshake зарезервирован для кадров; логи идут в stderr.

## Основные возможности

Все операции с контейнерами выполняются через подпроцессы `docker` с фиксированным argv, без shell; защищённые контейнеры нельзя остановить или удалить; `container.update` лишь изменяет лимиты ресурсов; `stats` — одноразовый сбор без тикера и опроса (G-19). Контракт конфигурации `container.config.get` / `container.config.set` определяет три реальные опции: `docker_bin`, `protected_containers`, `docker_timeout_ms` с китайскими label/help/default; приоритет `config.json` > окружение > значения в коде, сохранение вступает в силу сразу (`restart_required=false`).

## Граница безопасности

Список запретов и параметры обхода (exec / shell / attach) возвращают `E_UNSUPPORTED` до обращения к docker; список защищённых контейнеров предотвращает случайную остановку рабочих контейнеров; при недоступности docker.sock возвращается `E_NEED_ROOT` согласно ADR-0018 с указанием на канал повышения привилегий ядра, без предлагания группы docker (эквивалент root); не-Linux / отсутствие CLI / недоступный демон по-прежнему дают `E_UNSUPPORTED`. Плагин работает изолированным процессом с сокетом 0600; обход прав или подключение к чужому сокету является уязвимостью.

## Сборка и проверка

Ежедневная проверка — локальный `make check` (gofmt → go vet → go test -timeout 200s); перед выпуском `make dist` дважды с совпадающим sha256. GitHub Actions запускается вручную (`workflow_dispatch`), Gitea Actions — по тегам версий. `depth_level=basic`: основные пути работают, граничные случаи и внедрение отказов отложены до v1.1 — это позиционирование, а не функциональное понижение.
